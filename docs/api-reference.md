# Bramble HTTP API

Every route the macOS client talks to. Generated by hand against the code at
`bd8c0be`; the authority for response shapes is
`src/lib/api/views/views.types.ts`, which is where every field is assigned
explicitly and where the comments explaining each omission live.

See also `docs/import-api.md` for the design rationale behind the import
endpoints — this file is the contract, that one is the reasoning.

## Basics

**Base URL** — `http://localhost:3000` in development.

**Auth** — every `/api/v1/*` route and `/api/me` requires:

```
Authorization: Bearer <clerk session jwt>
```

Session tokens last about 60 seconds. Ask for one per request rather than
holding it; `AuthTokenProvider` on the client is shaped for exactly that.

**Caching** — every `/api/v1` response sets `Cache-Control: private, no-store`.

**Bodies are always objects, never bare arrays.** An array cannot grow a field.
`{ "events": [...] }` can later carry `truncated`; `[...]` can only be replaced,
and the client on the other end is a shipped app that cannot be rolled back.

### Dates

Every timestamp is ISO 8601 **with milliseconds**, because `toISOString()`
always emits them.

Swift's `.iso8601` decoding strategy **rejects fractional seconds**. Use:

```swift
let formatter = ISO8601DateFormatter()
formatter.formatOptions = [.withInternetDateTime, .withFractionalSeconds]
```

Getting this wrong surfaces as a decode failure that looks like a server bug.

### Errors

One envelope, every failure:

```json
{ "error": { "code": "NOT_FOUND", "message": "Storyline not found: …" } }
```

`fields` appears on validation failures, keyed by the offending path:

```json
{ "error": { "code": "VALIDATION_ERROR", "message": "…", "fields": { "turnId": "Required" } } }
```

`retryAfter` (seconds) appears on `RATE_LIMITED`, `UPSTREAM_BUSY` and
`GENERATION_TIMEOUT`.

| Status | Code                     | Meaning                                                                          |
| ------ | ------------------------ | -------------------------------------------------------------------------------- |
| 400    | `VALIDATION_ERROR`       | Malformed body or a path id that is not a uuid                                   |
| 401    | `UNAUTHORIZED`           | Missing, malformed or rejected bearer token                                      |
| 403    | `FORBIDDEN`              | Account deleted                                                                  |
| 404    | `NOT_FOUND`              | Unknown id — **or someone else's**. Never 403                                    |
| 409    | `CONFLICT`               | A turn already answered with a _different_ choice                                |
| 409    | `STORYLINE_NOT_READY`    | Storyline is not `ready` to play                                                 |
| 409    | `IMPORT_LIMIT_REACHED`   | All three conversation slots are spent                                           |
| 409    | `GENERATION_IN_PROGRESS` | Another generation holds this session                                            |
| 410    | `TRANSCRIPT_EXPIRED`     | Transcript gone before the worker read it. Re-send                               |
| 413    | `TRANSCRIPT_TOO_LARGE`   | Over 400,000 characters                                                          |
| 429    | `RATE_LIMITED`           | Our quota. Stop and tell the reader                                              |
| 429    | `UPSTREAM_BUSY`          | The model provider throttled us. Clears on its own                               |
| 500    | `GENERATION_UNUSABLE`    | Model output did not match the schema. Retrying burns money for the same failure |
| 500    | `INTERNAL_SERVER_ERROR`  | Unexpected                                                                       |
| 503    | `GENERATION_FAILED`      | Provider failure. Retryable                                                      |
| 504    | `GENERATION_TIMEOUT`     | Our own 60s deadline. Safe to retry                                              |

**404 and not 403 for another account's ids, everywhere.** "Not yours" and "no
such thing" are the same answer, or the error itself confirms the id exists.

## The world — what there is to play

### `GET /api/v1/world`

The twenty most engaging moments across every storyline the reader owns, best
first. This is the discovery surface: **most of these are beats the reader has
not reached**, and that is deliberate — you cannot offer "play from here"
without saying where "here" is.

Query: `?limit=` — optional, clamped to 20.

```json
{
  "events": [
    {
      "eventId": "uuid",
      "storylineId": "uuid",
      "storylineTitle": "The Unsent Apology",
      "title": "The apology that landed wrong",
      "description": "An apology was offered and waved away before it finished.",
      "occurredAt": "2026-04-02T18:00:00.000Z",
      "people": [
        { "id": "uuid", "name": "Blossom", "isSelf": true },
        { "id": "uuid", "name": "Maya", "isSelf": false }
      ],
      "score": 9,
      "weight": 1
    }
  ],
  "truncated": true
}
```

- **`score`** — 1–10, written by the model against an absolute rubric, so scores
  from different storylines are comparable.
- **`weight`** — 0..1, normalised across _this response_. Use it to size or
  colour; `score` is there so you can change that mapping without a server
  release.
- **`people`** — people, not per-storyline characters, so one human is one object
  however many storylines they appear in. Reader first, then alphabetical.
- **`occurredAt`** — null when the conversation did not date the beat.
- **`truncated`** — more rankable beats exist than were returned.

A reader with nothing gets `{ "events": [], "truncated": false }` and **200,
never 404**. Empty is an invitation, not an error.

Beats with no score are excluded entirely rather than ranked last — null means
nobody asked the model, which is not the same as the model judging a beat dull.

## People and arcs

### `GET /api/v1/people/{personId}`

```json
{
  "person": {
    "id": "uuid",
    "name": "Maya",
    "isSelf": false,
    "relationshipType": "oldest friend",
    "arcs": [
      {
        "storylineId": "uuid",
        "title": "The Unsent Apology",
        "setting": "Two flats and a group chat, March to June.",
        "tone": "wistful",
        "role": "supporting",
        "lastPlayedAt": null,
        "startable": true
      }
    ]
  }
}
```

`arcs` is ordered most recently played first; never-played fall to the back.
`startable` is false while a storyline is still generating or has failed.

Until several conversations are imported, every person yields the same single
arc with the same title. That is sparse data, not a bug — collapse the arc list
into the person screen when there is one entry.

### `GET /api/v1/storylines/{storylineId}`

```json
{
  "storyline": {
    "id": "uuid",
    "title": "The Unsent Apology",
    "setting": "Two flats and a group chat, March to June.",
    "tone": "wistful",
    "startable": true,
    "cast": [{ "id": "uuid", "name": "Maya", "isSelf": false }]
  }
}
```

**`cast` contains only people the reader has met** — those appearing in a beat at
or below their playhead. Extraction writes character descriptions having read the
whole conversation, and one really did read _"the investor who offers $300,000"_,
so an uncut cast puts the ending on the first screen.

No `arcSummary` and no `description`: both describe the whole arc.

## The play loop

Two calls. `turn` brings a session to a playable state and returns what to show;
`answer` records a decision and is deliberately fast.

### `POST /api/v1/storylines/{storylineId}/sessions`

Body optional:

```json
{ "mode": "resume", "fromEventId": "uuid" }
```

`resume` (the default) returns the existing playthrough if there is one; `new`
forces a fresh one. **201**, with the same `SessionView` the resume probe
returns.

**`fromEventId`** is how the world screen's "play from here" works: pass an
`eventId` from `GET /api/v1/world` and the new session's playhead lands **on**
that beat, so the story continues from it.

- It **always starts a fresh playthrough**, overriding `mode`. Handing back a
  half-finished session when the reader asked to begin at a particular beat
  would silently ignore the only thing they said.
- A beat from a different storyline, or one that does not exist, is a **404** —
  the id is resolved against the storyline named in the path.
- A malformed id is a **400** with `fields.fromEventId`.
- Picking a beat _behind_ another playthrough is fine. This starts a new session,
  so the monotonic playhead guard — which stops a retried generation walking a
  reader backwards _within_ a playthrough — never comes into it.

### `GET /api/v1/sessions/{sessionId}`

The resume probe. Free, no model call — call it on every launch rather than
reconstructing state locally.

```json
{
  "session": {
    "id": "uuid",
    "storylineId": "uuid",
    "state": "awaiting_answer",
    "turnsAnswered": 3,
    "turn": {
      "id": "uuid",
      "narrative": "She answers before you have finished typing.",
      "choices": [
        { "id": "uuid", "label": "Tell her the truth", "description": "It may not land." },
        { "id": "uuid", "label": "Change the subject", "description": null }
      ]
    }
  }
}
```

Three states, one remedy each:

| `state`           | What to do                           |
| ----------------- | ------------------------------------ |
| `awaiting_answer` | Render `turn` immediately            |
| `awaiting_turn`   | Call `POST .../turn`. `turn` is null |
| `blocked`         | The storyline is not playable        |

There is deliberately no state for "answered, consequences pending" — the remedy
is the same call, and every state named here is a branch the client carries
forever.

### `POST /api/v1/sessions/{sessionId}/turn`

The only paid endpoint. Settles any owed consequences, then generates.

No body. Returns `{ "turn": TurnView }` — the same shape nested in `SessionView`
above. Narrative and choices arrive **together**, so you hold the decision screen
before the reader has finished reading the beat above it.

Safe to retry: a second call finds the work done and costs a SELECT. Client
policy this is designed for — **single-flight per session**, jittered backoff, at
most three attempts, then a button. Never two concurrent.

Server deadline is 60s; past that you get `504 GENERATION_TIMEOUT`, which is
safe to retry.

### `POST /api/v1/sessions/{sessionId}/answer`

```json
{ "turnId": "uuid", "choiceId": "uuid" }
```

Returns `{ "turn": TurnView }`. Fast — one guarded UPDATE, no model call — so
fire `POST .../turn` immediately after and animate over the top of it. That
overlap is the whole latency budget of the loop.

`turnId` is the concurrency token, not a convenience: without it a screen
restored from the background can answer a turn the reader never saw.

**Self-reconciling.** Re-sending the _same_ choice returns 200, not 409, so a
lost response cannot strand you on an operation that succeeded. A _different_
choice is a real 409.

## Conversation import

Full rationale in `docs/import-api.md`. Three conversations per account, ever.

### `GET /api/v1/imports`

```json
{ "limit": 3, "used": 1, "imports": [ ImportView ] }
```

`used` counts only `ready`. Compute remaining as `limit - used - pending`, where
`pending` counts `queued` and `running` from the array.

### `POST /api/v1/imports`

```json
{
  "conversationKey": "conv_3fa29b0c1d7e4a55",
  "transcript": {
    "surface": "imessage",
    "messages": [
      {
        "isFromMe": false,
        "handle": "c_9b1e04a7d2f3c611",
        "sender": "Maya",
        "text": "…",
        "sentAt": "2026-03-02T19:04:00.000Z"
      }
    ]
  }
}
```

- **`handle`** must be `"me"` or `c_` + 16 hex. An allow-list, not a
  "looks like a phone number" check — anything else is a 400.
- At least 50 messages, at most 400,000 characters of text, oldest first.

**202** when newly accepted and queued. **200** when an import for this
`conversationKey` already exists and has not failed — same body, nothing
started. A `failed` import with the same key is re-queued.

Returns in milliseconds; extraction happens in a background job.

### `GET /api/v1/imports/{importId}`

Poll every ~5s while `queued` or `running`. One indexed row read, no Redis.

```json
{
  "import": {
    "id": "uuid",
    "conversationKey": "conv_…",
    "status": "running",
    "stage": "casting",
    "storylineId": null,
    "failure": null,
    "createdAt": "2026-10-01T19:04:00.000Z",
    "updatedAt": "2026-10-01T19:05:12.000Z"
  }
}
```

- **`status`** — `queued` | `running` | `ready` | `failed`.
- **`stage`** — `reading` | `writing` | `casting`, only while `running`.
  Extraction is one model call, so progress is stages and not a percentage.
- **`storylineId`** — set once `ready`.
- **`failure`** — `{ "code": "…", "retryable": true }` when failed. Re-send on
  retryable; stop and show the error otherwise.

**No response ever carries message content.** The `imports` row holds none
either — the transcript lives encrypted in Redis for at most 30 minutes and in
the memory of the worker reading it, and nowhere else.

## What is never returned

Not oversights. Each is a field a client might expect and must not get.

| Field                                                        | Why                                                                                                            |
| ------------------------------------------------------------ | -------------------------------------------------------------------------------------------------------------- |
| `stakes`                                                     | What is at risk in a beat — the lever the model writes with, and most of every beat the reader has not reached |
| `generationRationale`                                        | The model explaining its own trick                                                                             |
| `arcSummary`                                                 | Describes the whole arc, including beats above the playhead                                                    |
| `narrativeOrder`, `playheadOrder`                            | Internal ordering keys. Start sessions from `eventId`                                                          |
| `voiceProfile` / `sampleTurns`                               | Model-authored imitation of a real person's messages                                                           |
| `want` / `avoids`                                            | The authoring levers behind each character                                                                     |
| `clerkId`, `userId`, `sourceContactRef`                      | Identity and contact join keys                                                                                 |
| `durationMinutes`, `coverImageUrl`, any progress denominator | No honest backing — stories are endless, so "3 of 40" is both a lie and a spoiler                              |

A unit test stringifies every view and asserts none of these appear, so adding a
field by spreading a database row fails the build rather than shipping.
